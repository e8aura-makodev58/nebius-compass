# Hackathon plan review — Codex

Reviewed 2026-10-19 against plan v1 (`75fc934`), baseline `1e1c69c`, the supplied brief/rules/guide, and current source. One review pass; no implementation changes. This reviews the supplied rules transcription, not an independently authenticated live rules page.

The Investigator is a credible substantial addition for Best Apps and Agents: runtime Nemotron investigation, observed case citations, and operator approval go beyond a provider migration. Stage One remains the judges’ decision. Revise the following before assigning implementation; N1 can start after N0 establishes capabilities.

1. **BLOCKER — Model interpretation must not establish operational facts.** Plan §3, lines 82, 109–113, 142–143: the report creates an issue before equipment/class/symptom resolution is defined, then model classification appears to establish those facts. `project-state/concepts/agent-boundary.md` states application code owns facts, priority and eligibility; models only propose bounded events or rank supplied candidates. `backend/src/fault-truth.mjs:24–34` currently establishes engine-owned cause and observable symptom. **Change:** persist an unclassified report separately; code supplies allowed interpretation options, the model ranks them, and an operator confirms unresolved facts before code creates the dispatchable issue. For simulated reports preserve existing engine facts and treat classification as a hypothesis only. Keep priority deterministic. Record the guide conflict in decisions, rather than silently widening rule 3.

2. **BLOCKER — Approval needs enforcement at every assignment entry point.** Plan §3 lines 116–122 and §5 N3 promise no automatic dispatch but also say “Dispatch never stops” and allow `AUTO_APPROVE_SAFE`. `backend/src/live-assignment-service.mjs:89–107`, `:166–180` admit ordinary pending issues and create offers without an investigation gate. Existing background dispatch, manual override, offer acceptance, assistance and rematching can bypass a gate placed only in the new approval route. **Change:** define a code-owned dispatch gate shared by every assignment path, persist the exact authorized responder/fix and policy/operator identity, and revalidate current eligibility, safety, revision and issue state atomically on approval. Define expiry, restart, duplicate approval, supersession, rejection and escalation transitions. Specify explicitly that only unrelated legacy incidents continue autonomous dispatch. Restrict policy auto-approval to an explicit audited exception and test it separately from operator approval.

3. **BLOCKER — Tool and trace privacy require allowlists, not the existing marker scanner alone.** Plan §3 lines 95–98, 126–146. `backend/src/fault-truth.mjs:61–63` detects named keys/markers, not renamed numeric skill proxies or arbitrary text. `backend/src/live-schema.mjs:322–329` strips private attempt fields and checks responder truth; `backend/src/attempt-engine.mjs:159` separately redacts attempt internals. An archived issue/attempt bundle is not a safe case DTO. **Change:** define exact allowlisted DTOs for cases, tools, traces, public detail routes, fixtures and logs, excluding draws, probabilities, duration factors, latent cause labels and hidden-derived responder attributes. Build qualifications from independent public synthetic certification records, never `ResponderSkill`. Test both hidden-data noninterference (changing private truth does not change model packets) and canary scans, including renamed keys and archive-backed cases. Apply the same DTOs to error/repair messages and persisted traces.

4. **MAJOR — Narrative provenance and hypotheses can leak or invent diagnosis.** Plan §2, §3 lines 130–134: rejecting leaked cause text does not prevent paraphrased diagnosis, invented procedures or skill claims. Existing `backend/src/fault-truth.mjs:31–34` intentionally makes symptoms overlap; `project-state/concepts/agent-boundary.md` forbids diagnosing latent causes. **Change:** generate narratives solely from an explicit observable DTO; retain source and confirmed facts separately from untrusted text. Restrict hypotheses to bounded observable interpretations with evidence references, never engine cause identifiers. Legacy templates must use public symptoms, not the resolved cause. Test injection in retrieved historical narratives as well as the incoming report; all narrative text is untrusted through tools, repair and UI.

5. **MAJOR — Safety prerequisites and factual grounding are underspecified.** Plan §3 lines 99–113: membership of a cited case ID does not prove a prose claim, and specialist exclusion leaves `ISOLATION_REQUIRED` prerequisites unenforced. `backend/src/fix-catalog.mjs:29–40` currently permits only id/title/steps; there is no certification contract in `backend/src/context-engine.mjs:52–54` (eligibility is availability). **Change:** specify independent public qualifications and prerequisite states; unknown/unconfirmed prerequisites fail closed, including edits and alternatives. Return catalog procedure text verbatim and use structured evidence references to exact supplied fields/outcomes; bound qualitative explanation rather than promising arbitrary semantic claim verification. Define a deterministic safety-flag policy before inference, including outage and garbled-input behavior. Do not rely on Nano detecting injection or hazards.

6. **MAJOR — Temporal holdout must cover every evidence path.** Plan §4 lines 173–177 only hides cases after a split. `backend/src/fix-evidence.mjs:18` reads resolution history, `backend/src/context-engine.mjs:91–99` builds responder evidence from it, and compact facts survive retention (`backend/src/history-retention.mjs:64–80`). A cloned end-of-month seed can still expose held-out outcomes through aggregate fix/responder evidence, equipment history, narrative context or cached results. **Change:** define a decision-time cutoff over every tool and aggregate, using only outcomes completed before that instant; exclude the target case and future observations. Freeze the retrieval corpus or document a rolling-origin protocol. Add a future-data perturbation test proving all model-visible packets remain identical. Private engine truth stays in an isolated outcome runner; do not serialize cloned seeds into fixture or trace artifacts.

7. **MAJOR — Counterfactual comparison needs a paired experimental contract.** Plan §4 and §5 N5/N6: cloning a seed does not specify responder, workload, time, RNG, assistance, retries or abstention denominators. `backend/src/evaluation.mjs:41–70` is a deterministic assignment soak, not a fix counterfactual harness. **Change:** for the minimum replay compare first fixes with identical responder, engine state, time and random draws; hold all other decisions fixed. Define censoring/timeouts and treatment of abstained/escalated cases, report coverage plus paired denominators, and keep baseline evidence at the same cutoff. Defer whole-floor minutes comparisons until equivalence is tested. “Approved by policy” must not silently approve unsafe/abstaining cases.

8. **MAJOR — N1–N6 dates lack integration and contingency time.** Plan §5 targets N1 Oct 21, N2 Oct 23, N3/N4 Oct 25, N5 Oct 26 and N6 Oct 27. N1 awaits a key/probe, N3 introduces a new durable state machine plus routes and lane behavior, and N5 starts only after N3 although its contracts determine N2. Each merge also needs both suites. N6 requires a full regenerated month immediately afterward. **Change:** agree DTOs, fixture scenarios and replay protocol before N2; deliver one vertical slice (one report, one tool loop, approved action, negative case) first. Put go/no-go gates on N0 and that slice; if either slips, cut separate Nano triage, live narrative generation, analytics comparison, edit flow and whole-month regeneration first. Use a small deterministic investigation dataset plus the unchanged month if needed. Keep citations, safety, approval, abstention and real Nemotron proof. Do not describe six tool steps as one inference call; specify total attempts including repair and time/token budgets.

9. **MAJOR — Exclusive file ownership is asserted but not allocated.** Plan §5 N1–N6. N1 provider/role changes affect Settings consumed by main; N3 backend analytics feeds N4; N2 generator narratives and N6 seed share generator code; N5 main fixtures and Codex scenario tests share schemas. N3 routes and N4 stubs can both touch `server.mjs`; wiki/log and decision entries are shared too. **Change:** allocate named files and merge sequence: Codex owns provider, schema, route, runtime, retention and backend analytics code; main owns frontend and E2E; main owns scenario fixture data and harness, Codex imports its agreed version for tests. Main tunes prompts through config or hands edits back to Codex. Use separate fixture/stub modules, not main edits to backend routes. Allocate documentation pages and append-only entries per package. Add a case lookup API contract, missing despite clickable case IDs in §3 UI.

10. **MAJOR — Acceptance criteria need measurable failure and resource bounds.** Plan §3, §5 acceptance: total deadline, “bounded”, “agreement”, safety qualification, THIN/MODERATE/STRONG thresholds and “lane never holds the clock” have no values or exact definitions. §2 says thin evidence abstains, while §3 only forces abstention for NONE. **Change:** publish schemas/enums, explicit grade formula and thresholds, precedence of ESCALATE/ABSTAIN, deadline clock type and step/repair/call/token/result-byte limits. Test lane responsiveness with a deliberately unresolved provider promise; test bounded `/state`, archive equality and restart recovery. Citation validity 100% and violations zero must refer to accepted outputs, while invalid raw outputs, repairs, abstentions and fallbacks are counted separately. Define zero-denominator precision/recall. Version and identify recorded-live fixtures separately from synthetic fixtures; do not label invented responses as recorded Nemotron.

11. **MAJOR — Release gates need earlier ownership and demo-access resolution.** Plan §6 offers a cleaned fork as an alternative to confirming employer ownership; removing identifying material does not resolve ownership of inherited code. Supplied rules §4 require sole ownership, licensed integrations and free unrestricted judging access through Dec 15; plan §6 daily budgets/offline-default may exhaust the qualifying experience. **Change:** resolve publishing rights and dependency/asset licensing before N7, with owner confirmation recorded; a cleaned fork still needs rights. Define judge credentials/reserved capacity and recovery so budget exhaustion cannot deny evaluation. Keep genuine runtime inference available and distinguish replay footage. N0 facts should include official documentation evidence for model license, rate/context limits and prices; `/models` and probes alone cannot establish every contractual capability. No public release until those gates are satisfied.

12. **MINOR — Correct and qualify the audit claims.** Plan §1: `backend/src/context-engine.mjs:20–21` defines three floors, not two. Current counts are 54 files under backend/tests and 17 under e2e (counts include support files; count test patterns if claiming suite-file totals). `backend/src/event-planner.mjs:17` asks for generated symptom/action prose, so “short fixed descriptions” understates existing narrative generation: the gap is operator free-text intake and investigation, not all narrative generation. Eligibility currently means availability, not certification. `backend/src/evaluation.mjs:41–91` provides a deterministic soak/baseline comparison; identify that path precisely. Root commit/date and disabled upstream push match local git evidence. Public repository visibility cannot be inferred from missing local LICENSE/HACKATHON_CHANGES; mark visibility unverified pending an authorized remote check. Say the feature is intended to satisfy Stage One, not that it demonstrably passes; deterministic validators and fallback also make “every step runs on NVIDIA” inaccurate. Keep the deadline conversion and early submission buffer; clarify that the submission-build cutoff does not freeze ongoing product development (AGENTS rule 8).

Recommended assignment order: revise contracts and release gates now; N0 → N1 → minimal N2/N3 vertical slice, with main implementing N4 against frozen DTOs; then negative scenarios and paired replay; only then expand seed/UI polish. No implementation edits were made in this review.
